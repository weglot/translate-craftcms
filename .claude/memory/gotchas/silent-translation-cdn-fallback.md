---
name: silent-translation-cdn-fallback
description: A translated URL rendered in the source language with NO "Weglot error" comment is usually a non-200 from the translate endpoint — the scoped CdnTranslate falls back to the original words instead of throwing. Check the host the parser used first.
type: gotcha
---

Symptom: `/fr/…` renders in the source language, the switcher and hreflang are present, **no `<!--Weglot error … -->` comment and nothing in the Craft logs**.

Cause chain:
1. `ParserService::getClient()` picks the translate host: for a V2 key, the `api_base_url` option from the project settings, else `HelperApi::getApiUrlV2()`; for a V1 key, `HelperApi::getApiUrl()` (`src/services/ParserService.php:43-66`). Options are cached for 300 s under `weglot_cache_cdn` (`src/services/OptionService.php:157`) — a key that is **not** scoped to the API key, unlike the other `weglot_*` entries.
2. The scoped `CdnTranslate::handle()` rewrites `https://api.weglot.` to `https://cdn-api-weglot.` (`src/vendor/weglot/build/vendor-src/weglot-php/src/Client/Endpoint/CdnTranslate.php:27`), then for any chunk whose HTTP status is not 200 it appends the **original** words as translations (`:67-76`).
3. `$response` is therefore never empty and `throw new ApiError('All API calls failed')` (`:80`) is unreachable → no exception → `TranslateService::processResponse()` emits no error comment (`src/services/TranslateService.php:116-124`).

Typical triggers: a staging key against production hosts (`.claude/memory/gotchas/weglot-dev-env-normalization.md`), a stale `weglot_cache_cdn` after switching project, a host that 3xx-redirects the POST.

Diagnose: log (a) the host `ParserService::getClient()` chose, (b) the payload and status in `CdnTranslate::request()`, (c) HTML length before / after `$parser->translate()`. Fix on a site: clear the Craft data caches (or the "Reset settings" button → `OptionService::resetOptions()`, `src/services/OptionService.php:328`), then reload.

The vendor file is generated by php-scoper from `weglot-php` — never edit it; a fix belongs upstream, then `/vendor-update`.

**Why:** the same silent fallback was diagnosed on a customer site of the WordPress plugin (translate-wordpress `.claude/memory/gotchas/silent-translation-stale-api-host.md`, 2026-09-09); this plugin ships the same `weglot-php` code path, verified in the scoped vendor above.
**How to apply:** any "not translated, no error" report — check the host and the cached options before touching the parser.
